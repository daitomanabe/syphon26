# Syphon26 API Design

This document defines the first public API surface for Syphon26. Phase 1 is the native Syphon26 transport only. Classic Syphon bridge APIs are intentionally out of scope.

Status: Phase 1 API locked on 2026-05-24 for the native transport developer-preview surface. Any API change must update this document, `include/Syphon26/Syphon26.h`, and the compile-only examples in `Examples/APIUsage/`.

## Design Goals

- Provide a small, explicit server/client API for Metal-native frame sharing.
- Keep all fast-path frame operations on GPU resources.
- Avoid CPU texture readback in the publish and consume paths.
- Make synchronization, fallback modes, and dropped-frame behavior visible.
- Keep API names independent from classic Syphon classes.
- Support Objective-C callers and be comfortable from Swift.

## Module Surface

Public Objective-C headers for Phase 1 live under `include/Syphon26/`. `Syphon26.h` is the authoritative umbrella header; the per-type headers are forwarding headers for framework-style imports:

- `Syphon26.h`
- `Syphon26Server.h`
- `Syphon26Client.h`
- `Syphon26Directory.h`
- `Syphon26Frame.h`
- `Syphon26ServerDrawable.h`
- `Syphon26StreamDescription.h`
- `Syphon26Configuration.h`
- `Syphon26Diagnostics.h`
- `Syphon26Types.h`
- `Syphon26Error.h`

Private headers:

- `Syphon26SharedStatePrivate.h`
- `Syphon26RingBufferPrivate.h`
- `Syphon26XPCProtocolPrivate.h`
- `Syphon26SharedEventPrivate.h`
- `Syphon26IOSurfacePrivate.h`

Swift API is exposed by the `Syphon26` SwiftPM library target. Objective-C bridge headers lock the intended wrapper shape and are validated with `scripts/validate_api_examples.sh`.

## SwiftPM Integration Surface

The Swift library product is the Phase 1 embedding surface for Swift/AppKit/Metal apps:

- `Syphon26.version`
- `Syphon26.defaultControlPlaneMachServiceName`
- `Syphon26ControlPlane()`
- `Syphon26ControlPlane(machServiceName:)`
- `Syphon26ControlPlaneServiceMain.runDefault()`
- `Syphon26ControlPlaneServiceMain.run(machServiceName:)`

Cross-process apps must share one launchd-managed `Syphon26ControlPlaneService` Mach service. `Syphon26ControlPlane()` uses `Syphon26.defaultControlPlaneMachServiceName`.

## Core Types

### `Syphon26StreamID`

Stable stream identifier.

- Type: `NSString *`
- Generated by the server.
- Stable for the lifetime of one server instance.
- Never reused by another live stream.

### `Syphon26Sequence`

Monotonic frame sequence.

- Type: `uint64_t`
- Starts at 1 for the first published frame.
- Increments only when a frame is made visible to clients.

### `Syphon26HostTime`

Frame timestamp.

- Type: `uint64_t`
- Uses mach absolute host time.
- Converted to seconds only in reporting layers.

### `Syphon26PixelFormat`

Phase 1 should expose Metal pixel formats directly and map to CoreVideo only where needed.

- `MTLPixelFormatBGRA8Unorm`
- `MTLPixelFormatBGRA8Unorm_sRGB`
- `MTLPixelFormatRGBA16Float`

BGRA8 is the first required format. RGBA16F is required before the first benchmark release, but can land after BGRA8.

### `Syphon26ColorPrimaries`

- `Syphon26ColorPrimariesSRGB`
- `Syphon26ColorPrimariesDisplayP3`
- `Syphon26ColorPrimariesRec2020`
- `Syphon26ColorPrimariesUnspecified`

### `Syphon26TransferFunction`

- `Syphon26TransferFunctionSRGB`
- `Syphon26TransferFunctionLinear`
- `Syphon26TransferFunctionPQ`
- `Syphon26TransferFunctionHLG`
- `Syphon26TransferFunctionUnspecified`

### `Syphon26AlphaMode`

- `Syphon26AlphaModeOpaque`
- `Syphon26AlphaModePremultiplied`
- `Syphon26AlphaModeStraight`
- `Syphon26AlphaModeUnspecified`

### `Syphon26SyncMode`

- `Syphon26SyncModeAutomatic`
- `Syphon26SyncModeSharedEvent`
- `Syphon26SyncModeSequencePolling`

`Automatic` should prefer `MTLSharedEvent` when XPC handoff succeeds, then fall back to sequence polling.

### `Syphon26DeliveryMode`

- `Syphon26DeliveryModeLatest`
- `Syphon26DeliveryModeBoundedLatency`

Phase 1 default is `Latest`.

### `Syphon26FallbackReason`

- `Syphon26FallbackReasonNone`
- `Syphon26FallbackReasonSharedEventUnavailable`
- `Syphon26FallbackReasonSharedEventHandoffFailed`
- `Syphon26FallbackReasonIOSurfaceSecureHandoffUnavailable`
- `Syphon26FallbackReasonUnsupportedPixelFormat`
- `Syphon26FallbackReasonDeviceMismatch`

## `Syphon26ServerConfiguration`

Immutable configuration passed at server creation.

Required fields:

- `name: NSString *`
- `device: id<MTLDevice>`
- `width: NSUInteger`
- `height: NSUInteger`
- `pixelFormat: MTLPixelFormat`

Optional fields:

- `appName: NSString *`
- `slotCount: NSUInteger`
- `syncMode: Syphon26SyncMode`
- `deliveryMode: Syphon26DeliveryMode`
- `colorPrimaries: Syphon26ColorPrimaries`
- `transferFunction: Syphon26TransferFunction`
- `alphaMode: Syphon26AlphaMode`
- `privateStream: BOOL`
- `metadata: NSDictionary<NSString *, id> *`
- `allowsFallbacks: BOOL`
- `maximumProducerWaitNanoseconds: uint64_t`

Validation rules:

- `name` must be non-empty.
- `device` must not be nil.
- `width` and `height` must be greater than zero.
- `slotCount` must be 2 to 16. Default should be 3.
- Unsupported pixel formats must fail at initialization.

## `Syphon26Server`

Responsible for stream lifetime, slot allocation, publishing, and diagnostics.

### Creation

- `- initWithConfiguration:error:`
- `+ isSupportedOnDevice:reason:`

### Properties

- `streamID`
- `name`
- `appName`
- `device`
- `streamDescription`
- `isRunning`
- `activeClientCount`
- `configuration`
- `diagnostics`

### Lifecycle

- `- startWithError:`
- `- stop`
- `- invalidate`
- `- updateName:error:`
- `- updateMetadata:error:`

### Direct Render Path

This is the preferred zero-copy path. The producer renders directly into a Syphon26-owned slot texture.

- `- acquireDrawableWithTimeout:error:`
- `- presentDrawable:commandBuffer:timestamp:metadata:error:`
- `- discardDrawable:`

`presentDrawable` must publish only after the provided command buffer has encoded all producer writes. With shared-event sync, readiness is signaled from that command buffer.

### External Texture Path

Convenience path for apps that already rendered into their own texture.

- `- publishTexture:commandBuffer:timestamp:metadata:error:`

This path may encode a GPU copy or render pass into a Syphon26 slot. It must never use CPU readback.

### Reconfiguration

- `- reconfigureWithWidth:height:pixelFormat:error:`
- `- reconfigureWithConfiguration:error:`

Reconfiguration retires old slots, announces a new stream description version, and keeps the same stream ID when possible.

### Diagnostics

- `- diagnosticsSnapshot`
- `- resetDiagnostics`

### Handlers

- `clientDidConnectHandler`
- `clientDidDisconnectHandler`
- `streamDidStartHandler`
- `streamDidStopHandler`
- `errorHandler`

Handlers must never run on the frame hot path unless explicitly documented.

## `Syphon26ServerDrawable`

Represents a server-owned writable slot.

Properties:

- `texture`
- `sequence`
- `slotIndex`
- `width`
- `height`
- `pixelFormat`
- `streamDescription`

Rules:

- A drawable can be presented once.
- A drawable can be discarded.
- A drawable must not outlive the server.
- The server must not recycle a drawable slot until it is safe for producer and consumer GPU work.

## `Syphon26Client`

Responsible for attaching to one stream, acquiring frames, and exposing diagnostics.

### Creation

- `- initWithConfiguration:error:`
- `- initWithStreamDescription:device:error:`
- `+ isSupportedOnDevice:reason:`

### Properties

- `streamID`
- `streamDescription`
- `device`
- `isRunning`
- `isValid`
- `hasNewFrame`
- `latestSequence`
- `lastPresentedSequence`
- `configuration`
- `diagnostics`

### Lifecycle

- `- startWithError:`
- `- stop`
- `- invalidate`

### Frame Acquisition

- `- copyLatestFrameWithError:`
- `- copyLatestFrameWithTimeout:error:`
- `- copyLatestFrameForCommandBuffer:error:`
- `- releaseFrame:`

The returned frame wraps a Metal texture backed by the producer slot. The client must retain frame ownership until its GPU work no longer needs the texture.

### Callback Consumption

- `newFrameHandler`

The handler indicates that a newer sequence is available. The handler should not force one IPC message per frame; notification coalescing is allowed.

### Diagnostics

- `- diagnosticsSnapshot`
- `- resetDiagnostics`

### Handlers

- `newFrameHandler`
- `streamDidRetireHandler`
- `streamDidChangeDescriptionHandler`
- `errorHandler`

## `Syphon26Frame`

Represents a client-visible frame.

Properties:

- `texture`
- `sequence`
- `timestamp`
- `width`
- `height`
- `pixelFormat`
- `colorPrimaries`
- `transferFunction`
- `alphaMode`
- `metadata`
- `streamDescription`
- `requiresGPUWait`

Methods:

- `- encodeWaitOnCommandBuffer:error:`
- `- markConsumedWithCommandBuffer:`
- `- close`

Rules:

- Frames are immutable.
- Frame texture access is read-only from the client perspective.
- `close` releases client ownership if no command buffer is supplied.
- `markConsumedWithCommandBuffer:` lets Syphon26 delay slot reuse until consumer GPU work completes.

## `Syphon26Directory`

Discovers Syphon26 native streams. It does not discover classic Syphon streams in Phase 1.

APIs:

- `+ sharedDirectory`
- `- startWithError:`
- `- stop`
- `- streams`
- `- streamWithID:`
- `- streamsMatchingPredicate:`
- `- addStreamChangeHandler:`
- `- removeStreamChangeHandler:`

Stream change handlers must be coalesced and must not be tied to the frame hot path.

## Native Control Plane

Phase 1 uses an internal XPC control channel for stream metadata and lifecycle registration. The frame hot path remains Metal/IOSurface-based; XPC is control-plane only.

The Swift developer-preview surface exposes `Syphon26ControlPlane` for endpoint-backed or launchd Mach-service-backed connections, `Syphon26ControlPlaneServer` for embedded same-process bootstrap, and `Syphon26ControlPlaneServiceMain` for a launchd-managed helper process. The Objective-C wrapper header keeps these bootstrap details out of the Phase 1 app-facing API.

Internal messages:

- producer registration
- producer retirement
- consumer registration
- consumer retirement
- stream list query

The current control-plane payload exchanges typed stream metadata, IOSurface references, `MTLSharedEventHandle`, and compact shared-state snapshots. Those payloads remain private implementation details and should not become public API unless an advanced use case requires them.

## Bridge APIs Out Of Scope

Classic Syphon compatibility is deliberately not part of Phase 1. The locked native API must not expose:

- classic `SyphonServer` or `SyphonClient` wrappers
- OpenGL texture publishing or receiving APIs
- classic Syphon discovery compatibility
- bridge-specific metadata normalization
- APIs that expose raw IOSurface IDs, raw shared-memory pointers, or XPC handles as public contracts

Future bridge work should be implemented as a separate adapter layered around the native Syphon26 transport.

## API Rules

- Public objects must be thread-safe unless explicitly documented otherwise.
- `start`, `stop`, and `invalidate` must be idempotent.
- Server names should be stable across frames.
- A server must not recreate the stream for every frame.
- Frame callbacks are hints, not ownership transfer.
- Clients must tolerate skipped sequences.
- No public API should expose raw shared-memory pointers.
- IOSurface IDs and XPC handles should remain implementation details unless a future advanced API requires them.
